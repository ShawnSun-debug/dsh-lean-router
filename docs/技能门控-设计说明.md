# 技能门控 - 设计说明（票 06）

本文件是票 06 的交付物之一：技能门控层（lib/skillgate.js + lib/skill-provider.js 升级）的设计与验收依据。
约束以交接契约台账为准；本文件不覆盖台账，只做落点说明。

## 0. 频率结论（验收 4）：provider.list() 是缓存的，门控走回退方案

**结论：宿主对 provider.list() 的调用是"每 (cwd, scopeChain, revision) 一次"，不是每轮一次。**

证据（实读宿主 0.2.2-rc.5 源码，@deepseek-ai/dsh-skill/lib/index.js）：

- L224-226：list(options) = (await this.snapshot(options)).skills。
- L234-240：snapshot = collect(options) + 排序。
- L265-297：collect() 先查 collectCache（key = collectCacheKey(cwd, scopeChain, revision)，L395-401），命中直接返回；未命中才 collectFresh 并在可缓存时写入 collectCache（L288-294）。
- L331-375：collectFresh -> collectLayer -> listLayerCandidates，其中 **L350 `output = await waitWithAbort(provider.list(options), options.signal)` 是 provider.list() 的唯一调用点**。
- L376-380：invalidateCache() 把 revision += 1 并清空缓存 —— 只有 provider 注册/销毁等层变更才触发；普通轮次不触发。

因此**每轮门控不能依赖 list() 被重新调用**。按契约验收 4 的回退方案实现：

1. lib/skill-provider.js 的 list() 恒返回全量 31 技能（全量可见；invocation 与 rank 语义不变）。
2. 每轮打分/挂载/近场提示由 lib/skillgate.js 在注入缝执行（见 §6 注入点）。
3. 审计的 decision.mode 固定写 "fallback-cached-list"，标注这是缓存降级模式。

## 2. 每轮评分（约束 5）：双信号，31 个技能全打一遍

门控只在**显式传入状态**时生效：isGateActive(state) 要求 state.taskText 为非空字符串
（无路由状态 = 门控关闭 = list() 全量、round() 不产出、审计不写 —— 约束 2 的向后兼容）。

**信号 A（分类标签映射）**：复用 lib/bands.js 的 classifyTask（react/spec/weak 关键词计数带）
与 isComplexTask，映射到矩阵 scenario 场景：

| 路由带 | 场景加分（sceneMap） |
|---|---|
| react（build） | engineering +2、process +1 |
| spec（fix/排查） | engineering +2、research +1 |
| weak（自路由） | 无场景加分（仅关键词信号） |
| isComplexTask=true | engineering 再 +1（complexBoost，深度任务偏工程） |

**信号 B（关键词命中）**：矩阵每技能 keywords 逐个大小写不敏感匹配任务文本（前 4000 字符截断）；
命中一个关键词 +1（按命中关键词个数计，不按出现次数）。矩阵 keywords 现全空（_meta.keywords_policy
为"先空着，实测后再填"），故默认分数由信号 A 主导；主人填词后无需改码。

**总分** = 信号 A + 信号 B。**阈值可配**（resolveGateConfig）：autoScore（默认 2，高于 = 自动挂载）、
hintScore（默认 1，高于 = 近场提示）、tokenBudget（默认 8000）、charsPerToken（默认 4）、
sceneMap/complexBoost/arbitration 全部数据驱动可配。

## 3. ds-* 场景裁决（约束 1）：数据驱动可配，只改放行档位

裁决表 arbitration（默认，可整体替换）：

| 场景 | prefer | 语义 |
|---|---|---|
| engineering | ds | 写码类 ds-* 优先：ds-* 活跃时（state.dsActive 含任一 "ds-" 前缀），该场景 mattpocock 技能从 auto 降档为 hint |
| process | mattpocock | 流程类 mattpocock 优先（ds-* 不覆盖该场景，规则为空操作但入审计） |
| 其余场景（meta/research/writing/teaching/setup） | （未列出） | passThrough：不裁决 |

**裁决只影响放行集合**（auto→hint 降档），**永不改 invocation** —— 列表候选的
invocation 字段原样保留；门控出口按"模型通道"过滤时只排除非 model-invocable 技能，
这一过滤依据的是矩阵 invocation 本身，不是裁决结果。

## 4. 分档与软降级（约束 8）

- classifyTiers：仅 model-invocable 技能参与 auto/hint（user-only 技能保持全量可见、走 /skill 人工点名）；
  score >= autoScore → auto，hintScore <= score < autoScore → hint，其余 off。
- arbitrate：裁决降档（见 §3）。
- degrade：渲染后的近场文本估算 token（ceil(chars / charsPerToken)）超过 tokenBudget（默认 8000）时，
  把"低分"auto 技能降为 hint —— 得分升序、名字序次之（确定性）；**个数不设上限，只有总量软保险**
  （主人定案）。被降级者记入 decision.degradations。invocation 不变。

## 5. 审计（约束 4）：格式先出，通道内嵌，供票 07 消费

- 通道：createAuditChannel({ capacity = 256 }) —— 内存环形缓冲 + subscribe(fn) 订阅 +
  drain() 取走 + entries() 只读快照。**默认不落盘**（产物边界白名单内没有审计日志路径）。
- 格式版本：每条审计带 v: 1（AUDIT_FORMAT_VERSION）；格式变更必须升版本。
- 每条 skillgate-round 记录字段：
  - ts（ISO 时间）、turn、task（band/complex/head 前 120 字）、dsActive、
    config（autoScore/hintScore/tokenBudget/charsPerToken 快照）。
  - scores：**31 个技能全量**，每条 { name, score, signals: { category: { band, scene, points, complex }, keywords: [命中词] }, model, user } —— 得分与命中信号都可审计（约束 5）。
  - decision：{ band, complex, auto[], hint[], arbitrations[], degradations[], estTokens, budgetTokens, mode: "fallback-cached-list" }。
  - estimateText：本轮实际渲染的近场文本（审计里可直接复核 token 估算的输入）。
- 落点：makeProvider({ audit }) 注入同一通道（provider 显式门控路径复用）；
  round(state, catalog, config, audit) 也可独立调用（接线方自带通道）。

## 6. 注入点（接线由 master 集成；本票只交模块与常量）

- 建议通道：ctx.systemPrompt.context({ name: "lean-router:skills", order: 221, text })
  （常量 GATE_CONTEXT_NAME）。与 lib/router.js 的近场引导同通道类型：
  同一决策下文本恒定 → 宿主 deepEqualJson 判等即零写入、缓存友好。
- **禁走 agent/pre-step append**：dsh-agent-loop L679-698 的 pre-step 是 waterfall 决策点、
  L755 每步调用；经它追加的非 runtime-context 消息会被宿主 durable 写历史、每步累积
  （票 05 设计说明已论证），违反缓存友好约束。
- 首轮捕获参照：dsh-agent-loop L106 agent/inbox/claimed（payload 含 message/turn）。
- round() 的输入 state = { taskText, turn, dsActive? }：taskText 取当轮用户消息
  （同 router 捕获判据 message.source.kind === "user"）；dsActive 由接线方从宿主技能目录
  观察（"ds-" 前缀即 ds-* 家族）。
- 门控关闭时：round() 返回 { active: false }，近场通道返回空串，list() 全量 —— 与票 02
  scaffold 行为逐字节一致。
