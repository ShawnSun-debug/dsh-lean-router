## 客户端插件技术契约（本次逆向所得，别重新踩）

- 入口文件 `lib/client.js`，形式：`window.__ModuleLoader__.load({ id: "包名", factory: (require) => { ... return { apply } } })`
- `factory(require)` 里的 `require` 取**宿主提供的模块**：`react`、`react-dom`、`react/jsx-runtime`、`@deepseek-ai/dsh-client-ui-primitives` 等；插件自身依赖不打包
- 插件导出 `{ apply, inject }`（cordis 形）；`apply` 可为 generator，`yield` 的 effect 卸载时自动回收
- UI 注册：`ctx.slots.register({ name, id, order }, Component)`；另有 `ctx.inject(slotName, () => ctx.register({...}, C))` 写法（dsh-cost-meter 用后者）
- 正文视图 API 另有一条：`ctx.uiConversation.views.register({ target, ... })`（dsh-client-ui-trajectory 用），但它是会话事件流视图，静态面板不建议走
- 加载条件：`dsh-client-modules` 扫描**宿主 Loader entries** 中声明了 `dsh.client` 的包，且要求 `exports["./client"]` 存在，否则抛「client bundle not found; run `pnpm run build` before launch」
- 参考实现（npm 安装目录里可反编译看）：`dsh-cost-meter`、`dsh-ops`、`dsh-smooth-stream`

## 陷阱与教训（都是这轮真实踩过的）

1. **preset 的 plugins 里绝不能挂宿主层服务插件**（如 `ptc-runtime`）——preset 在独立 scope 激活，重复挂载会让整条 preset 注册失败、从预设列表消失（1.0.3 事故）
2. **cordis 插件的 apply 不能返回普通对象**——返回值必须是 dispose 函数 / null / undefined / thenable，否则真宿主报 `Invalid effect`（1.0.2 事故）
3. **`dsh plugin add` 会做 overlay 校验**，YAML 缩进错会让整个安装回滚
4. **别信 CI 全绿**：模块测试与真机装配是两件事，上述两次事故 CI 都绿
5. **`ui/go.json` 不是 dsh 原生机制**——它是给第三方 dsh-Go 用的，而用户环境**没装 dsh-Go**（`@stardustlc` 是空目录），别指望它渲染面板
6. **`propose_action`（个性化页面）在本会话工具面里不存在**——虽然 `dsh-personalized-recommendations` 已装且工具真实存在，但没暴露出来，所以官方「页面卡片」通道走不通
7. **npm 发布**：默认 registry 是 npmmirror（只读），必须 `--registry=https://registry.npmjs.org`
8. 在 PowerShell 里重定向 YAML 用 `Out-File -Encoding utf8`（`*>` 会写 UTF-16，js-yaml 报 null byte）
